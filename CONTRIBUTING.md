# Contributing to probelm

Thanks for contributing. Keep changes focused, observable, and compatible with the documented `probelm` command.

## Before opening a pull request

1. Read `CLAUDE.md`, `CODE_OF_CONDUCT.md`, and `SECURITY.md`.
2. Use a focused branch based on the repository default branch.
3. Keep user-facing documentation in English in `README.md` and update `README_ID.md` and `npm/README.md` in the same change when the interface changes.
4. Preserve the legacy executable for existing users. New documentation must use `probelm`.
5. Do not commit API keys, personal data, generated release archives, or local configuration.

## Development

```bash
make check-all
```

Individual checks:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features --locked
cargo package --locked --allow-dirty
npm --prefix npm pack --dry-run
npm --prefix npm run selftest
```

## Commit and pull request rules

Use Conventional Commits, for example:

- `feat: add capability filter`
- `fix: handle gateway timeout`
- `docs: update installation instructions`
- `ci: build release archives`

One pull request should represent one coherent change. Explain behavior changes, compatibility impact, and the checks you ran. Release versions and changelog entries are generated by Release Please.

## Distribution changes

Release asset names are shared by six consumers: the release workflow, both installers, the npm installer, Homebrew, and Scoop. Update all consumers together and verify archive extraction plus checksum validation. Distribution credentials belong only in GitHub trusted publishing or repository environments; never place them in source files.
